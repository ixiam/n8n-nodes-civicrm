# JWT Authentication Implementation - Client Summary

## Overview

We have implemented **CiviCRM JWT (JSON Web Token) authentication** for the n8n node to provide enhanced security and follow industry best practices for external integrations.

---

## Why Server-Issued JWT?

After thorough technical investigation of CiviCRM's API architecture, we chose **server-issued JWT tokens** (generated by CiviCRM) rather than client-side signing with Site Key. Here's why:

### The Short Version

| Aspect | Benefit |
|--------|---------|
| **Token Lifetime** | Automatically expires after 1 hour (configurable). Leaked tokens have limited window of access. |
| **Security Standard** | Follows OAuth 2.0 best practices used by Google, Microsoft, AWS, and Stripe. |
| **No Key Extraction Risk** | Signing happens entirely on CiviCRM server. Your credentials never need to be exposed. |
| **Automatic Refresh** | n8n transparently requests new tokens when needed. Zero manual intervention. |
| **Full Fallback** | If JWT fails, automatically uses API Key. Workflows never break. |

### Why NOT Site Key?

CiviCRM's architecture **requires** that JWT tokens be signed with internal cryptographic keys that:
- ✗ Cannot be extracted via API (security by design)
- ✗ Differ from Site Key (different credential, different purpose)
- ✓ Can only be used by CiviCRM's internal process

**Result:** Only CiviCRM can generate valid JWT tokens. This prevents external parties from forging tokens — a critical security requirement.

---

## How It Works (For Non-Technical Stakeholders)

```
Traditional API Key Approach:
  Client holds API Key indefinitely
  └─ If leaked: attacker has permanent access
  └─ Revocation: requires regenerating key across all systems

JWT Approach:
  Step 1: Client sends API Key to CiviCRM (once)
  Step 2: CiviCRM generates short-lived token (1 hour)
  Step 3: Client uses token for next hour
  Step 4: Token auto-expires (no manual revocation needed)
  Step 5: Client requests new token automatically
  └─ If leaked: attacker has 1 hour window only
  └─ Revocation: automatic when key regenerated
```

**Analogy:** Like a temporary access badge that expires daily, vs a permanent ID card.

---

## Security Benefits

✅ **Time-Limited Access** — Tokens automatically expire, reducing exposure window  
✅ **No Key Exposure** — Signing happens server-side; your keys never leave CiviCRM  
✅ **Permission Scoping** — JWT tokens are tied to specific user accounts with their permissions  
✅ **Full Audit Trail** — CiviCRM logs all token generation for compliance & security monitoring  
✅ **Industry Standard** — Same approach as every major SaaS platform (OAuth 2.0)  

---

## Implementation Details

**For CiviCRM Administrators:**
- AuthX extension must be enabled (v5.48+)
- X-Civi-Auth header authentication enabled
- No manual key management needed (CiviCRM handles it automatically)

**For n8n Users:**
- Just toggle "Enable JWT Auth" in credential settings
- Everything else is automatic
- Contact ID is auto-resolved (no manual entry)
- Smart fallback to API Key if JWT unavailable

**Performance:**
- First request: Minimal overhead (generates JWT once)
- Subsequent requests: No overhead (uses cached token)
- Auto-refresh: Transparent (happens before expiry)

## Comparison: API Key Only vs JWT

| Feature | API Key Only | JWT Authentication |
|---------|---|---|
| **Setup** | Simple | Simple (toggle in UI) |
| **Token Lifetime** | Indefinite | 1 hour (auto-refreshing) |
| **If Exposed** | Permanent access until revoked | Limited to 1 hour |
| **Revocation** | Manual regeneration | Automatic on key rotation |
| **Security Compliance** | ⚠️ Basic | ✅ OAuth 2.0 Standard |
| **Audit Trail** | Limited | Full (CiviCRM logs) |
| **Permissions** | Site-wide | Contact-scoped |
| **Recommended For** | Development/testing | Production workflows |

## Frequently Asked Questions

**Q: Do I have to use JWT?**  
A: No, API Key authentication still works. JWT is optional and recommended for enhanced security.

**Q: What if JWT stops working?**  
A: Automatic fallback to API Key ensures workflows never break.

**Q: How often do I need to regenerate tokens?**  
A: Never. n8n handles everything automatically. Tokens refresh transparently.

**Q: Can I configure the token lifetime?**  
A: Yes, in the n8n credential settings (default 1 hour).

**Q: Does JWT cost extra?**  
A: No, it's included in the AuthX extension (available with CiviCRM 5.48+).

**Q: Is this secure?**  
A: Yes, follows OAuth 2.0 standards used by Google, Microsoft, and AWS.

## Getting Started

### Step 1: Enable AuthX in CiviCRM
1. Go to **Administer → System Settings → Authentication**
2. Enable **X-Header Authentication**
3. Set **JWT in X-Civi-Auth header** ✓

### Step 2: Configure in n8n
1. Create CiviCRM credential
2. Enter Base URL and API Key
3. Toggle **Enable JWT Auth** ✓
4. Save and test

### Step 3: Use in Workflows
1. Select credential from dropdown
2. Build workflow normally
3. Enjoy automatic JWT security ✓

**Setup Time:** ~5 minutes
